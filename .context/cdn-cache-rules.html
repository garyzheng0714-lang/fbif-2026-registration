CDN 缓存规则详解

为什么需要配置规则？每条规则的作用是什么？

先搞清楚一件事：CDN 不知道你的网站长什么样

你把域名接到了 CDN，CDN 就像一个新来的快递员，他不知道哪些包裹可以提前备货在仓库（缓存），哪些必须每次都去工厂现拿（回源）。

类比：便利店进货

你开了一家便利店（CDN 节点），需要告诉店员：

  • 矿泉水、零食（静态文件）→ 大量囤货，卖完再补 → 缓存 30 天
  • 现做咖啡（表单提交 API）→ 不能囤，每杯都要现做 → 不缓存
  • 今日菜单（首页 HTML）→ 每天都在变，必须实时更新 → 不缓存

如果你不告诉他，他会按默认规则乱来 —— 可能把「现做咖啡」也囤货了，顾客喝到的就是凉的。

你的网站有哪些「路径」？

当用户打开 fbif2026ticket.foodtalks.cn，浏览器会请求以下内容：

🌐
用户打开网站
浏览器发起请求
→
📄
index.html
首页，告诉浏览器
需要加载哪些文件
→
📦
/assets/index-xxx.js
页面代码和样式
（文件名每次构建都不同）
→
📡
/api/submissions
提交表单数据
（每个人的数据都不同）

这些路径的性质完全不同，所以需要不同的缓存策略：

缓存 30 天 /assets/* JS/CSS 静态文件，文件名含哈希，内容永远不变
不缓存 /api/* 表单提交、获取验证码等动态接口
不缓存 / 首页 HTML，每次更新后内容都会变
不缓存 /.well-known/* HTTPS 证书续期验证，必须回源
不缓存 /health 服务器健康检查
不缓存 /metrics 服务器监控指标

如果不配规则会怎样？

不配规则（默认行为）

CDN 可能把 /api/* 的响应也缓存了。

结果：用户 A 提交表单后，用户 B 提交时拿到了用户 A 的结果（因为 CDN 返回了缓存的响应）。

更严重：CSRF 验证码被缓存，所有人拿到同一个 token，表单全部提交失败。

正确配置规则后

/api/* 设为不缓存，每个请求都回源。

每个用户拿到自己的 CSRF token，提交各自的表单数据。

同时 /assets/* 缓存 30 天，全国各地的用户都能秒开页面。

最严重的后果：API 被缓存 = 网站「瘫痪」 表单看起来能打开，但提交永远失败。用户以为网站坏了。而且这个问题很难排查 —— 因为你在自己电脑上测试可能是好的（CDN 节点缓存内容不同）。

6 条规则详解

在阿里云 DCDN 控制台的「缓存配置」→「缓存规则」中，按以下顺序添加：

顺序很重要！ 规则是从上到下匹配的。如果把「/ 不缓存」放在「/assets 缓存 30 天」前面，那 /assets 也会变成不缓存，因为 / 先匹配到了。
# 路径 缓存 为什么？
1 /.well-known 不缓存 HTTPS 证书续期
你的服务器每 90 天需要续期 HTTPS 证书。续期时，证书机构会访问这个路径来验证你是域名拥有者。如果 CDN 把验证结果缓存了，续期会失败，90 天后网站 HTTPS 会失效。
2 /api 不缓存 表单提交、验证码等所有接口
每个用户的请求数据都不同（姓名、手机号、证件号），绝对不能缓存。缓存了就会串数据。
3 /health 不缓存 健康检查
监控系统定期访问这个地址确认服务器是否正常。缓存了就检测不到服务器宕机。
4 /metrics 不缓存 监控指标
实时性能数据，必须是最新的。
5 /assets 缓存 30 天 JS、CSS 等静态文件 —— CDN 加速的核心
这些文件名里有哈希值（如 index-BpFqvz53.js），内容一旦发布就不会变。缓存 30 天，全国用户都从最近的 CDN 节点拿，不再占用你服务器的 1Mbps 带宽。
6 / 不缓存 兜底规则 —— 包括首页 HTML
用户访问网站首先加载 index.html。这个文件每次发布都会变（里面引用了新的 JS 文件名）。如果被缓存，用户会一直看到旧版本。

一张图看懂：用户访问时发生了什么

配置规则后的请求流程：

  1. 用户打开网站 → 浏览器请求 /（首页 HTML）
    规则 6：不缓存 CDN 每次都去你的服务器拿最新的 HTML
  2. 浏览器读到 HTML，发现需要加载 /assets/index-BpFqvz53.js
    规则 5：缓存 30 天 CDN 发现本地有缓存 → 直接返回，不需要去服务器拿
  3. 页面渲染完成，用户填写表单，点击提交 → 请求 /api/submissions
    规则 2：不缓存 CDN 透传到你的服务器，服务器处理并存入数据库
  4. 完成！ 静态资源走 CDN 缓存（快），动态请求走源站（安全）

更新前端后，CDN 缓存的旧文件怎么办？

完全不用担心，自动更新。 原因在于我们的文件命名策略：每次构建都会生成不同的文件名。
更新前

index.html 引用：

/assets/index-ABC123.js

CDN 缓存了这个文件 ✓

更新后

index.html 引用：

/assets/index-DEF456.js

新文件名！CDN 没有缓存 → 去源站拿 → 缓存新文件 ✓

旧文件 ABC123 还在 CDN 上，但没人请求它了（因为新 HTML 指向 DEF456），30 天后自动过期清除。

总结：6 条规则的核心逻辑

能缓存的尽量缓存（/assets → 30 天）
给用户提速，给服务器减压

不能缓存的绝对不缓存（/api、/、其他）
保证数据安全、内容实时、功能正常
